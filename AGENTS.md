# Repository Guidelines

## Project Structure & Modules
Rust workspace crates live under `asp/`, `cli/`, `client/`, and `crates/*` (Merkle/hash utilities and the pool account abstractions). Cairo contracts are in `pool/`, Circom sources sit under `circuits/`, and verifier artifacts are generated into `verifier/` and `pool/src/verifier`. Shared scripts and automation live in `scripts/`.

### Target Directory Structure
Build outputs are organized to prevent conflicts:
- `target/dev/` - Cairo contract artifacts from `scarb build`
- `target/circuits/` - Circom outputs (witness generators, r1cs, zkeys)
- `target/debug/` - Rust debug builds

**Important**: `scarb build` does NOT delete `target/circuits/`. Keep circuit artifacts separate!

## Build, Test, and Development

### Initial Setup
Run `./scripts/setup.sh` to:
1. Install Python venv + garaga
2. Compile circuits to `target/circuits/`
3. Generate proving keys and verification keys
4. Update Cairo verifier constants
5. Build Cairo contracts

### Verifier Architecture
The Groth16 verifier in `pool/src/verifier/groth16_verifier.cairo` is a custom implementation that wraps garaga. Key points:
- **Constants file**: `groth16_verifier_constants.cairo` is auto-generated by garaga and copied during setup
- **Verifier contract**: The main verifier is NOT overwritten by garaga - we maintain a custom version
- **ECIP class hash**: The verifier uses a compile-time constant `ECIP_OPS_CLASS_HASH` for the garaga ECIP contract. This is required because `__validate__` uses library_call which cannot access contract storage
- If you change the UniversalECIP contract in `pool/src/ecip.cairo`, you must update `ECIP_OPS_CLASS_HASH` in the verifier to match

### Daily Development
```bash
# After changing Cairo contracts:
scarb build
cargo build -p client  # Picks up new contract artifacts automatically

# After changing circuits (rare):
./scripts/setup.sh

# Run tests:
cargo test
```

### Manual Circuit Compilation
```bash
circom2 circuits/pool.circom --r1cs --wasm --sym --c --output target/circuits
npx snarkjs groth16 setup target/circuits/pool.r1cs target/circuits/pot16_final.ptau target/circuits/pool_0000.zkey
```

## Coding Style & Naming
Default to Rust 2021 idioms: four-space indentation, snake_case for modules/functions, UpperCamelCase for types, and SCREAMING_SNAKE_CASE for constants. Run `cargo fmt --all` before committing and keep `cargo clippy --all-targets --all-features -D warnings` clean. Cairo modules in `pool/src` follow Scarb formatting via `scarb fmt`, and Circom files should retain the existing block-commented style and descriptive signal names.

## Testing Guidelines
**Prerequisites**: Ensure Python venv is activated with garaga installed (`source .venv/bin/activate && pip install -r requirements.txt`). The `garaga` CLI is required for ZK proof generation in tests.

`cargo test` spins up Katana automatically; use `USE_EXISTING_DEVNET=1 cargo test` to target a manually launched `katana --chain-id SN_SEPOLIA`. Prefer integration-style coverage around Starknet interactions by adding cases near the calling crate (e.g., `asp/src/*` or `cli/src/*`). When touching Cairo code, pair it with `scarb test` once suite coverage lands, and document any Katana ports or account files needed for reproducibility.

## Commit & Pull Request Guidelines
Follow the existing Conventional Commit flavor (`fix(build): …`, `feat(cli): …`) to keep the history searchable. Each PR should describe the user-facing behavior, list required setup (e.g., regenerated `target/circuits/*.zkey` files), and link issues or Starknet proposal threads when applicable. Include test evidence—`cargo test`, `scarb build`, or CLI transcripts—and add screenshots only when UI artifacts from `client/` change. Keep branches short-lived and rebase before requesting review.

## Security & Environment Notes
Never commit proving keys, secrets, or `account-file.json` contents. Confirm Katana is recent enough to expose `BlockTag::Pending`, and avoid mixing devnet implementations. When sharing logs, redact addresses used for live deployments and double-check `.env` artifacts stay local.
